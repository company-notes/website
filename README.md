# Company Notes · Website

The multilingual website for **https://company-notes.com/**, maintained by the [`company-notes`](https://github.com/company-notes) GitHub organization.

**Stack:** MkDocs Material + built-in Blog plugin, Markdown, GitHub Actions and GitHub Pages. No backend, database or separate CMS.

## 1. Create the repository

Create a **public** repository named **`website`** under `github.com/company-notes` (suggested URL: `https://github.com/company-notes/website`). Put the **contents** of this ZIP at the repository root and push to `main`.

```bash
git init
git add .
git commit -m "Initialize Company Notes website"
git branch -M main
git remote add origin https://github.com/company-notes/website.git
git push -u origin main
```

If GitHub created a README automatically, clone that repo first and copy these files into it instead.

## 2. Enable GitHub Pages (one-time)

In **Repository → Settings → Pages → Build and deployment**, set **Source = GitHub Actions**.

In **Custom domain**, enter **`company-notes.com`** and save. The `CNAME` generated by the build is **not enough** for an Actions deployment; the domain must also be set in GitHub's Pages settings.

At your DNS provider, point the apex `company-notes.com` to GitHub Pages using these four `A` records:

| Type | Host | Value |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

If your registrar offers `ALIAS`/`ANAME`, that can also be used as supported by GitHub. Optional `www` CNAME should point to `company-notes.github.io` (not to the `website` repo path). **Verify your domain** in the organization Pages settings if available; enable **Enforce HTTPS** once DNS and certificate validation are complete.

**Important:** add/verify the custom domain in GitHub **before** pointing DNS, to avoid a domain-takeover window.

A push to `main` triggers `.github/workflows/pages.yml`. Look under the **Actions** tab for the build and deployment. This repository does not require a `gh-pages` branch or a Personal Access Token.

## 3. Language URLs

| Language | Public URL | Source directory |
| --- | --- | --- |
| 繁體中文 (default) | `https://company-notes.com/` | `content/zh-hant/` |
| English | `https://company-notes.com/en/` | `content/en/` |
| 简体中文 | `https://company-notes.com/zh-hans/` | `content/zh-hans/` |

A language dropdown is provided by Material for MkDocs. Our small `site.js` keeps the corresponding article path when changing languages (as long as the localized page exists). Articles published in all three languages share the same `slug`.

**Why no i18next / `mkdocs-static-i18n`?** This is a *deliberate* design choice. The Material **Blog** plugin has documented incompatibilities with the static-i18n plugin. Three independent MkDocs builds are boring, robust and SEO-friendly. The homepage is pre-rendered in every language, so no client-side translation is needed. This also means the site is functional with JavaScript disabled.

## 4. How to publish a new post

Create **three `.md` files with the same filename**, one in each language's `blog/posts/` folder:

```text
content/
  zh-hant/blog/posts/2026-11-01-organization-design.md
  en/blog/posts/2026-11-01-organization-design.md
  zh-hans/blog/posts/2026-11-01-organization-design.md
```

Each file must start with front matter like:

```yaml
---
title: "如何設計 AI 公司組織"
date: 2026-11-01
slug: organization-design
categories:
  - Organization
---

# 如何設計 AI 公司組織

文章簡介。

<!-- more -->

正式內容從這裡開始……
```

Translate `title` and body text, but **keep `date`, `slug` and the filename identical** across languages. The slug makes every post's URL stable:

- `/blog/organization-design/`
- `/en/blog/organization-design/`
- `/zh-hans/blog/organization-design/`

Blog indexes, category indexes, archive pages and pagination are automatically generated. Use `<!-- more -->` to control the snippet shown in the blog index.

### Writing Chinese first

Create a draft with `draft: true` in the `zh-hant` post front matter. The checker lets untranslated drafts remain unfinished. **Only remove `draft: true` when the English and Simplified Chinese files are ready.** This intentionally prevents half-published translations or language-switch dead ends. The built-in blog plugin excludes drafts from production builds.

Post updates trigger a new Pages build automatically on push. No need to edit navigation.

## 5. Preview locally

Python **3.12** recommended:

```bash
python -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python scripts/build_site.py
python -m http.server 8000 --directory site
```

Open http://localhost:8000/ , http://localhost:8000/en/ and http://localhost:8000/zh-hans/ .

For live-reload while editing **Traditional Chinese** content:

```bash
python scripts/build_site.py --prepare-only
python -m mkdocs serve
```

Live-reload runs only the default language. Run the full `build_site.py` for a final three-language check.

## 6. Repository layout

```text
website/
├── .github/workflows/pages.yml       # Auto-deploy on push
├── mkdocs.yml                       # Default zh-Hant config
├── requirements.txt
├── scripts/
│   ├── build_site.py               # Builds 3 language trees
│   └── check_content.py            # Ensures translated published posts
├── shared/                         # Edit common CSS/JS/icons here
│   ├── stylesheets/site.css
│   ├── javascripts/site.js
│   └── assets/{logo,favicon}.svg
├── overrides/main.html             # Language SEO alternates
└── content/
    ├── zh-hant/                    # Source language, published at /
    ├── en/                         # Published at /en/
    └── zh-hans/                    # Published at /zh-hans/
```

## 7. How to edit branding and links

- Homepage: `content/{language}/index.md` (custom HTML structure allowed within Markdown).
- Editorial writing: `content/{language}/blog/posts/*.md`.
- Playbooks and toolkit pages: `content/{language}/playbooks/`, `toolkit/`.
- Fonts, layout, responsive CSS: `shared/stylesheets/site.css`.
- Navigation text: `mkdocs.yml` for zh-Hant, `scripts/build_site.py` for EN and zh-Hans.
- Repository and business links: edit `mkdocs.yml` plus relevant Markdown.

The demo launch post is intended as a starter and can be replaced before going live.

## 8. Notes

- Articles are **not** automatically machine translated. You supply/edit the three Markdown translations; the workflow publishes them.
- Build dependencies use compatible version ranges. Consider pinning exact versions after the first successful build.
- This project does **not** deploy until you push it to your own repository and complete GitHub Pages / DNS setup.
